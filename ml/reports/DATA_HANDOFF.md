# Data: baseline трёх тем

Результат на 28 октября 2026 года: подготовлены тексты Lenta.ru, группы и явные токены,
обучен и сохранён baseline, выполнены временная оценка и проверка контракта бота.
Дополнительно подготовлен TTS-пилот и проверена цепочка через существующий WhisperASR.
Это учебный baseline со слабой разметкой, не подтверждённая модель для эксплуатации.

## Темы и источник

| Внутренняя метка | Ответ бота | Что отбираем |
|---|---|---|
| education | образование | Учёба, школы, вузы, курсы, экзамены, учебные программы |
| entertainment | развлечения | Фильмы, сериалы, музыка, концерты, игры |
| technology | технологии | Устройства, операционные системы, приложения и софт |

Пользователь подтвердил: научно-популярный текст сам по себе не считается образованием.
Происшествие со школьником тоже не должно получать education только из-за статуса участника.
Исходный корпус — [Lenta.ru v1.1](https://github.com/yutkin/Lenta.Ru-News-Dataset):
800 975 строк, поля `url`, `title`, `text`, `topic`, `tags`, `date`.
SHA-256 архива: `c4f7f771c7c78221978943a65dfabc9cc129a72a5d477635acc16a771d1fda47`.

Разметка **автоматическая, предварительная**: рубрики/теги и правила по заголовку.
Entertainment использует теги «Кино», «Музыка», «Игры» и признаки содержания;
technology — «Гаджеты», «Софт» и технический предмет; education — явные образовательные
сочетания. Отбрасываются конфликты правил, многие происшествия и бытовые сюжеты.
Все правила доступны в `ml/scripts/lenta_data.py`; это не готовая редакционная
разметка именно наших трёх классов.

Явную лицензию на исходные тексты в репозитории Lenta не нашли. Публичный архив
не следует описывать как разрешение на любое использование или как отдельную
«лицензию для исследовательских целей».

## Подготовка и разделение

Удалены короткие тексты (меньше 30 слов), пустые идентификаторы и точные дубли по
полным текстам, заголовкам, URL и фактическим входным фрагментам. Нормализация дублей:
нижний регистр, `ё → е`, схлопывание пробелов. Заголовок, topic, tags и URL не входят
в признаки модели. Вход — первые 140 слов тела статьи.

| Часть | Период | Всего | На класс |
|---|---|---:|---:|
| Train | 1999–2017 | 3 066 | 1 022 |
| Validation | 2018 | 183 | 61 |
| Test | 2019 | 366 | 122 |

Итого **3 615 текстов**. Классы балансируются внутри каждой части с фиксированным
seed 20261028. Дата берётся из поля date; 5 аномальных дат вне диапазона исключены.
Документы, просмотренные в предыдущих аудитах, исключены из новых holdout по
списку хешей `previous_review_ids.txt`. Семантически близкие новости об одном событии
пока не сгруппированы: отсутствие точных пересечений не доказывает отсутствие всех утечек.

Результат подготовки — `ml/data/lenta_v3/{train,validation,test}.jsonl`,
метаданные, SHA-256 каждой части. Поля записи: `id`, `url`, `date`, `title`, `text`,
`label`, `label_source`, исходные `topic`, `tags`.

## Токенизация и модель

В sklearn Pipeline: lowercase → стандартный word tokenizer → TF-IDF униграмм/биграмм
→ классификатор. Лемматизация и удаление стоп-слов не применяются. TF-IDF и словарь
обучаются **только на Train**. Словарь содержит 40 000 признаков и сохраняется вместе
с моделью, а также отдельно в `ml/models/vocabulary.json`.

Явные токены каждой записи: `ml/data/lenta_v3/*_tokens.jsonl` с id и меткой.
Всего токенов: Train — 371 056; Validation — 21 475; Test — 44 122.
Эти числа относятся к word tokens, а не к размеру словаря или числу bigram-признаков.

Сравнены две фиксированные конфигурации:

| Модель | Validation macro-F1 |
|---|---:|
| LogisticRegression, C=1 | 0,9619 |
| MultinomialNB, alpha=0.5 | **0,9673** |

Выбран **TF-IDF + MultinomialNB** по Validation. Test не использовался для обучения
и выбора модели. На Test: accuracy **0,9754**, macro-F1 **0,9756**.
Константный классификатор: accuracy 0,3333, macro-F1 0,1667.

| Класс | Test precision | Test recall | Test F1 |
|---|---:|---:|---:|
| education | 0,9380 | 0,9918 | 0,9641 |
| entertainment | 1,0000 | 0,9672 | 0,9833 |
| technology | 0,9916 | 0,9672 | 0,9793 |

**Это согласие с предварительными метками, а не доказанная семантическая точность.**
Метаданные, версии библиотек, матрица ошибок, проверки и SHA-256 весов находятся
в [baseline_metrics.json](baseline_metrics.json).

## Проверка разметки и ограничения качества

После фиксации v3 ассистент просмотрел по 10 тестовых заголовков с первыми 25 словами:
education — 8 совпадений и 2 явных происшествия; entertainment — 7 совпадений и
3 неоднозначных сюжета; technology — 10 совпадений. Это небольшой диагностический
просмотр ассистентом, **не независимая человеческая разметка** и не оценка accuracy.
Решения сохранены в `ml/data/lenta_v3/assistant_review.csv`, сводка —
[label_audit.json](label_audit.json). Ошибки не удалялись из Test задним числом.

Отрицательный словарь неполон: например, «побили» и «выстрелил» могут пройти отбор
образования. Политические и судебные сюжеты в культурных рубриках тоже неоднозначны.
Следовательно, корпус нельзя выдавать за полностью проверенную вручную разметку.
Для следующей итерации полезна полная смысловая проверка education и новый gold-test
на целевых коротких сообщениях; уже просмотренный Test не использовать для скрытого тюнинга.

v1/v2 использовались для выявления ошибок отбора; их метрики несопоставимы напрямую
с v3, поскольку отличаются правила и разделение. История v2 сохранена в `history/`.
Технологии в этом baseline представлены в основном устройствами и софтом, а не всем
разнообразием технических тем. Классы сбалансированы искусственно. Корпус старый.

## TTS и стык с Speech

Создано **27 WAV**: по 3 примера класса в каждой части, 16 кГц, mono PCM16,
русский голос macOS Milena, 170 слов/минуту, до 45 слов текста на аудио.
Общая длительность — около 607 секунд. Manifest связывает аудио с исходной статьёй,
меткой и split; аудио наследует разделение исходного текста.

На 9 тестовых аудио через существующий `WhisperASR` (tiny, CPU/int8):
правильная тема относительно weak labels — **8/9** и на исходных коротких фрагментах,
и после ASR; macro-F1 — **0,8857** в обоих случаях. Micro-WER — **0,3861**.
Нормализация WER: нижний регистр, ё→е, word tokens; числа и аббревиатуры не разворачиваются.
Ошибка классификации существовала уже на исходном фрагменте, до Whisper.

Это маленькая проверка интеграции на одном синтетическом голосе, не качество
распознавания человеческой речи. Детали: [tts_metrics.json](tts_metrics.json),
транскрипты — `ml/data/tts_v3/asr_predictions.jsonl`.
Использовались официальные [Systran/faster-whisper-tiny](https://huggingface.co/Systran/faster-whisper-tiny)
на ревизии `d90ca5fe260221311c53c58e660288d3deb8d356`; SHA-256 model.bin проверен
по LFS-метаданным. При сетевой ошибке библиотеки модель была скачана curl с того же
официального источника и передана локальным путём. Код Speech не изменялся.

## Воспроизведение

Из корня репозитория:

```bash
uv sync --locked --group ml
uv run --group ml python -m ml.scripts.download_lenta
uv run --group ml python -m ml.scripts.lenta_data
uv run --group ml python -m ml.scripts.train_text_baseline
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

Ноутбук: [01_lenta_baseline.ipynb](../notebooks/01_lenta_baseline.ipynb).
Его ячейки выполнены в окружении проекта; коммитится версия с очищенными выводами.
Для полного повторения в ноутбуке установите `REBUILD = True`.

Опциональный TTS (macOS с установленным русским голосом):

```bash
uv run --group ml python -m ml.scripts.make_tts_sample
uv run --group ml python -m ml.scripts.evaluate_tts --whisper tiny
# Если Whisper уже скачан:
uv run --group ml python -m ml.scripts.evaluate_tts --whisper ml/models/whisper-tiny
```

`--per-class 0` у TTS озвучивает весь подготовленный корпус, а не только пилот.
На других ОС для экспорта потребуется другой TTS-движок. Подготовка, обучение и
инференс не зависят от macOS.

## Стык с ботом и передача

```python
from newsbot.classifier import build_classifier

model = build_classifier("tfidf", model_path="ml/models/text_baseline.joblib")
prediction = model.predict("В университете начался прием абитуриентов")
```

Возвращается `newsbot.schemas.TopicPrediction`, confidence 0..1. Пустой текст и
полностью неизвестный словарь дают «другое», confidence=0. Для остальных сообщений
вне трёх классов надёжное отклонение не реализовано. `min_confidence` можно задать
явно, но порог нужно оценивать на целевых данных. Confidence не калиброван по gold-меткам.
По умолчанию factory по-прежнему использует stub; backend выбирает MLOps/бот.

Веса, данные, токены, аудио и CSV с текстами **не коммитятся**. Архив данных нужно
распаковать в `ml/data/`, архив модели — в `ml/models/`. Обученный файл уже содержит
словарь и TF-IDF; переобучение в боте не нужно. `manifest.json` содержит SHA-256 весов.
Использовать версии из uv.lock; они отличаются от окружения старого локального v1.
CI устанавливает группу ml, чтобы проверки backend не пропускались из-за зависимостей.

Часть Data заканчивается воспроизводимым baseline и переданными артефактами.
Дальше команда подключает backend в сервисе, Speech развивает ASR, MLOps настраивает
хранение/DVC и деплой. Независимый человеческий gold-test и оценка реальной речи
остаются отдельным улучшением качества, а не уже выполненной проверкой.
